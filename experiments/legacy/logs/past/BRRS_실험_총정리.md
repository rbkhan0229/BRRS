# BRRS 실험 총정리 — delayed-RX와 lead margin의 정체

2026-07-03/04 기준. 모든 수치는 32sym(PLEN 32), 채널 9, PAC8, DW3000 기준 실측.

---

## 0. 무엇을 알아내려 했나

출발 질문: **"lead margin은 왜 결정적으로 중요하고, tail margin은 왜 아무 효과가 없는가?"**

답을 찾는 과정에서 얻은 것: 수신기 내부 동작의 정량 모델, 실패 원인 진단 체계,
프리앰블 단축의 진짜 비용, 그리고 논문 논리의 뼈대.

---

## 1. 먼저 알아야 할 그림 (배경지식)

### 프레임은 3부로 온다
```
[프리앰블 32sym ≈ 32.6µs][SFD ≈ 8.1µs][데이터 (PHR+PSDU) ≈ 175µs]
                                ↑ RMARKER (타임스탬프 기준점)
```
- **프리앰블** = 같은 패턴의 반복. 내용 없음. 수신기가 "채널 지도(CIR)"를 만드는 재료
- **SFD** = "지금부터 본편" 표시
- **데이터** = 진짜 내용. 프리앰블로 만든 채널 지도를 써서 읽음 (지도가 흐리면 깨짐)

### 수신기는 4단계로 일한다 (앞 2단계는 매번 심볼을 잡아먹는 고정비용)
1. **기동** (~11µs): 켜기 명령 후 실제로 들리기까지의 예열. 이 동안 지나간 신호는 유실
2. **검출** (~12~24sym): 8심볼 묶음(PAC8)씩 상관시켜 "프리앰블 맞다"를 확정. 기록 안 남음
3. **누산** (남은 심볼): 채널 지도에 심볼을 겹쳐 쌓음. 이 개수가 **accumCount**
4. SFD 찾고 데이터 복조

### delayed-TX와 delayed-RX의 비대칭 (버그의 온상)
- delayed-**TX**: 프로그램한 시각 = RMARKER 발사 시각. 칩이 프리앰블을 알아서 미리 쏨
- delayed-**RX**: 프로그램한 시각 = 수신기 **켜기 시작** 시각. 아무 보정 없음
  → 코드가 프리앰블 길이를 손으로 역산해서 미리 열어야 하고, 기동 지연도 코드 책임

### 수신 감시 체계 — 단계마다 감시견이 따로 있다

| 단계 | 감시자 | 실패 시 로그 | 비고 |
|---|---|---|---|
| 탐색 (프리앰블 검출 전) | FWTO (dwt_setrxtimeout) | fwto | **FWTO의 관할은 여기까지** |
| 검출 → SFD | SFD 타임아웃 (33심볼) | sfdto | 검출 시점부터 카운트 시작 |
| PHR 읽기 | PHR 오류 검사 | phe | |
| 데이터 읽기 | RS/CRC 검사 | fsl / fce | |

- FWTO는 프리앰블 검출에 성공하는 순간 임무 종료. 타이머 만료가 진행 중인 수신을
  중단시키지 않음 (실측: 창 끝 318µs < 프레임 끝 341µs인데 1000/1000 성공, fwto=0).
  → tail margin이 무의미한 하드웨어적 이유
- SFD 타임아웃 33심볼 = "예측"이 아니라 **상한선**: 검출이 프리앰블의 어느 지점에서
  일어났든, 진짜라면 최악의 경우에도 (PLEN+1+SFD−PAC)심볼 안에 SFD가 반드시 지나감.
  안 지나가면 노이즈 오검출이었다는 뜻 → RXSTO. lead를 키워도 이 값은 늘릴 필요 없음
- 각 런의 실패 유형(fwto/sfdto/phe/fsl)은 어느 단계에서 죽었는지를 그대로 가리킴

### PAC 그리드 — 왜 소비량이 8의 배수가 아닌가

수신기는 **자기가 듣기 시작한 시각** 기준으로 신호를 8심볼 묶음(PAC8)으로 자른다.
프리앰블은 이 그리드의 중간 어딘가에 도착하므로:

**소비량 = 8 × (판정에 필요한 묶음 수) − (프리앰블 도착의 그리드 내 위치 0~8)**

- 앞항은 8단위 양자화, 뒷항은 연속값 → 소비량은 아무 정수나 가능 (20, 21, 23...)
- lead를 1µs 늘리면 그리드가 1심볼 이동 → 소비량이 1씩 미끄러짐 (스윕의 램프.
  단, 2µs 간격으로 측정하면 2씩 뛰어 보임)
- 미끄러짐이 묶음 경계를 넘으면 필요한 묶음 수가 ±1 → 소비량 8 점프 (스윕의 절벽)

### 절벽 (PER의 성질)
PER은 SNR에 비례해 서서히 나빠지지 않는다. 임계 SNR 위에선 ~0%, 아래에선 ~100%,
전이 구간은 몇 dB. 프레임별 SNR은 분포(±5dB)이므로,
**PER = 분포의 왼쪽 꼬리가 절벽에 잠긴 비율.** 평균이 절벽 근처면 환경 1~2dB 변화에
PER이 자릿수로 요동한다. (32sym 평균 27.6dB — 절벽 근처. 64sym 35dB — 안전)

## 2. 실험 연대기 — 각 실험이 밝힌 것

### E1. plen 스윕 (기존): 32sym만 조건부로 죽는다
64/128/256sym은 PER 0%, 32sym은 margin 설정에 따라 0.2% ↔ 100%.
→ 문제는 32sym 근처의 어떤 한계선.

### E2. lead vs tail (기존): 비대칭의 발견
같은 조건에서 lead-only는 0.2%, tail-only는 **100% 실패**.
→ 원질문 성립. "도착이 결정적인데 왜 창이 늦나?"라는 미스터리 발생.

### E3. 코드 리뷰: 미스터리의 해부
- 도착이 결정적(UWB RX offset min=max)이라는 건 **지터가 0**이라는 뜻이지 정렬됐다는 뜻이 아님.
  창 열림에는 **상수 바이어스**(절사 오차 0.7µs + 미모델 기동 지연)가 있었음
- 상수 바이어스 → 실패도 상수적 (0% 아니면 100%의 계단) — 관측과 일치
- 수정: 프리앰블 길이 올림 계산, RX timeout 단위(µs→UUS), **진단 로깅 추가**
  (timeout을 fwto/pto로, 에러를 sfdto/phe/fce/fsl로 세분화 + accumCount + 창→RMARKER 오프셋)

**UUS 수정이란**: `dwt_setrxtimeout()`에 넘기는 숫자의 단위는 µs가 아니라 UUS(UWB
microsecond, 512/499.2MHz = 1.0256µs)다 (User Manual RX_FWTO, API Guide에 명시).
구코드는 µs 값을 그대로 넘겨서 창이 의도보다 2.56% 길었다 (예: 415 → 실제 425.7µs).
`US_TO_UUS()` 올림 변환 매크로를 넣어 의도한 길이와 실제를 일치시켰다.
성능에는 영향 없음(수신이 시작되면 창 끝은 무의미하므로) — 문서/재현성 정확성을 위한 수정.

### E4. 단위 해프닝: margin의 단위는 µs
"margin100 = 100ms 아닌가?" → 로그의 RX_WIN=415us가 100µs임을 증명.
이후 로그에 LEAD/TAIL 값을 직접 출력하도록 수정 (재현성).

### E5. 장소 비교: 세기 ≠ 품질
| 장소 | 32sym PER | 실패 유형 |
|---|---|---|
| 0.5m open space (가깝고 트임) | 1.8~3.2% | 날에 따라 fwto 또는 sfdto/phe |
| 1m office (TX 보일러실 차폐) | 0.0~0.2% | — |

가까운 쪽이 20배 나쁨. 원인: 책상 반사가 직접파와 같은 CIR 탭에 겹쳐 상쇄(멀티패스).
차폐는 세기를 깎지만 절벽 위에만 있으면 무해 — **PER를 정하는 건 세기가 아니라 첫 경로의 구조.**
→ 32sym의 진짜 비용 = 환경 민감성 (64sym은 어디서든 0%)

### E6. lead 스윕 ① (0~15µs): 문턱과 기동 지연 실측
| lead | PER | 실패 | accum |
|---|---|---|---|
| 0/2/4 | 100% | 전부 fwto (검출 자체 실패) | — |
| 6 | 4.0% | sfdto 34 (검출은 100% 성공, SFD에서 탈락) | 8 |
| 8 | 0.1% | — | 10 |
| 10 | 0.4% | — | 12 |
| 15 | 0.8% | — | **9 ← 이상 신호** |

- **문턱 = lead 4→6µs 사이**
- accum이 lead 1µs당 1심볼 회수 → **기동 지연 δ ≈ 11µs** 실측
- **실패의 2단 구조**: lead≤4 = 검출 절벽(fwto), lead=6 = 복조 절벽(sfdto), lead≥8 = 정상
- lead=15에서 accum 감소(9) → "검출 비용은 상수"라는 모델에 균열 → E7로

### E7. lead 스윕 ② (12~20µs): PAC 톱니의 발견
| lead | PER | accum |
|---|---|---|
| 12 | **0.00%** | **14** |
| 14 | 3.9% | **8/16 양봉** (절벽 바로 위) |
| 16 | 0.3% | 10 |
| 18 | 0.1% | 12 |
| 20 | **0.00%** | **14** |

**accum = 8 + ((lead − 6) mod 8.14µs)** — 톱니파.
- 검출 비용은 상수가 아니라 PAC 정렬 위상에 따라 8심볼(1 PAC) 단위로 양자화
- 주기가 8.0이 아니라 8.14µs(PAC8 실시간 길이)임을 lead=100 포인트(accum 12)가 판별
- **PER는 accum의 함수**: 8→~4%, 9→0.8%, 10→0.1~0.3%, 12→0.0~0.4%, 14→0.00%

## 3. 최종 모델 (한 장 요약)

```
프리앰블 32.6µs 예산의 소비 내역:

[창 지연으로 유실]  [기동 δ≈11µs 중 프리앰블과 겹친 부분]  ← lead로 제거 가능
[검출 12~24sym (PAC 정렬에 따라 양자화)]                  ← 고정비용, 제거 불가
[누산 accum = 남은 것]                                    ← 이게 성능을 결정

lead margin  → 유실 제거 + 정렬 위상 선택 (accum 극대화)
accumCount   → 채널 지도의 해상도 → SNR → PER (절벽 함수)
tail margin  → 도착 지터가 0이고, 수신 시작 후엔 창 끝이 무시되므로 (fwto=0으로 확인) 무의미
```

**원질문의 답**:
- lead가 결정적인 이유 = 기동 지연 ~11µs 보상 + 검출·SFD에 최소 accum ~8 필요 (전부 실측)
- tail이 무의미한 이유 = 프레임은 늦게 도착하는 일이 없고(지터 < 1µs),
  일단 수신이 시작되면 창 끝 타임아웃은 적용되지 않음

**권장 설정**: lead = 18µs (톱니 정점 12/20은 절벽에서 2µs라 온도/개체 표류에 취약.
18은 ±2µs 표류에도 accum 10~14 유지), tail = 0.

## 4. 논문 논리 (4단)

1. **줄인다**: 프리앰블 32sym으로 오버헤드 절감 (짧은 프레임일수록 이득 큼)
2. **타이밍 장벽은 lead margin으로 제거** — 100%→0%, 메커니즘과 수치 전부 실측 (E3, E6, E7)
3. **남는 SNR 한계는 극복이 아니라 감지**: accumCount = 공짜 링크 건강 지표
   → 프리앰블 길이 적응 (accum 낮으면 64sym으로 승격) — 시스템 기여로 제안 가능
4. **손익 계산**: 실효 슬롯 = 슬롯/(1−PER). 32sym은 PER < 4.4%면 64sym 대비 순이득
   (1m office 0~0.4% → 확실한 이득)

## 5. 벤더 문서 대조 (DW3000 User Manual v1.1, DWM3000 Data Sheet Rev B)

| 우리의 실측/결론 | 매뉴얼 근거 |
|---|---|
| delayed RX는 "켜기 시작" 시각일 뿐, 보상 없음 | §4.3: "the receiver **turn-on** time is programmed into DX_TIME... then the IC receiver is turned on" |
| 타임아웃(FWTO 등)은 창 열림 시점부터 카운트 | §4.3: "This point marks the start time for any programmed timeouts" |
| 수신이 시작되면 창 끝(FWTO)은 프레임을 못 끊음 → tail 무용 | §4.5 FWTO: "A valid receive frame arrives... This **stops** the receive frame wait timer" |
| 예약이 늦으면 delayed late (HPDWARN) | §4.3: HPDWARN "lateness" condition 설명 |
| SFD 타임아웃은 프리앰블 검출 시점부터 → 긴 lead에도 sfdTimeout 증가 불필요 | RXSTO: "The SFD detection timeout starts running **as soon as preamble is detected**" |
| 톱니 주기 ≈ 8µs = PAC8 | SNIFF §: "PAC size is 8 symbols, (this is approximately 8 µs)" |
| 기동 지연의 구성 요소 | SNIFF §: "**Allow 5µs for the RX RF block to be stable**" — 실측 ~11µs 중 5µs는 RF settle, 나머지 ~6µs는 디지털 획득 체인(비공개) |
| 드리프트 무시 가능 (2ppm × 10.4ms ≈ 21ns) | DWM3000 DS §2.1: 크리스털 공장 트림 < 2ppm |
| lead=12(절벽 인접)는 온도 표류에 취약 → 18 권장 | UM §: "re-calibrate if the operating temperature changes by 20°C" |
| 매뉴얼에 없는 우리 고유 측정 | 총 사각시간 11µs, 검출비용 12~24sym 양자화, accum 톱니 공식, 최소 생존 accum ~8, accum→PER 매핑 |
