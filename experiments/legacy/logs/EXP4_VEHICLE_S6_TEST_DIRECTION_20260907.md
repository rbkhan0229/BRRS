# BRRS Exp4 시험 방향 — 최종 차량·TX 6대

## 최신 확정 배치 및 준비 점검

사용자 확정: 프렁크 RX 1대, 범퍼 TX 2대, 1열 운전석/조수석 TX 각 1대, 트렁크 TX 2대. 총 RX 1 + TX 6이다. 현재 마지막 탑재 후보는 이후 실행한 PAC4/SFD timeout 64·13슬롯이며 N4 PER 4.25%로 목표 미달이다. 아래 PAC8 최종 상태 표기는 그 이전 캠페인의 이력이다.

2026-09-07 15:24 KST SSH·7개 보드와 로컬/원격 후보 HEX·수집 도구를 읽기 전용으로 확인했다. 차량의 짧은 예비 비교를 위한 펌웨어는 준비됐으며, 차량 배선·현장 네트워크·긴 확인용 구성은 별도 준비 대상이다. 사용자 시간 제약을 반영한 상세 순서는 [차량 준비 상태 및 실행 계획](exp4_vehicle_readiness_20260907/VEHICLE_PLAN.md)에 정리했다. 이 점검에서 추가 빌드·플래시·RF 실행은 하지 않았다.

## 2026-09-07 후속 실행 완료

사용자의 진행 승인 후 현재 집 배치를 유지한 채 물리 TX 6대·12/13 DATA 슬롯으로 7회 측정했다. 12슬롯 PAC8 기준 1회와, 13슬롯에서 추가 슬롯을 N2/N3에 각각 배정한 PAC8 → PAC4 → PAC8 비교 6회다. 신규 역할은 N5=1050208509, N6=1050227627, N7=1050204212로 확인하고 플래시했으며 기존 INIT/N2/N3/N4 역할은 유지했다.

모든 예정 송신 90,000회가 성공했고 비컨 누락·예약 지연·RDB/SPI/수집 오류는 없었다. N4 PER은 PAC4에서 7.55%/7.15%로 앞뒤 PAC8보다 낮았지만 각 노드 PER <1% 목표는 7회 모두 실패했다. 나머지 5개 노드는 모든 실행에서 0~0.1%였다. 현재 최종 장비 설정은 TX 6대·13슬롯·PAC8, sequence 2345672345673(추가 슬롯 N3)이다. 원본 런타임 소스와 원본 Git 상태를 보존했으며 GitHub 업로드는 계속 보류한다.

전체 결과: [실험 보고서](exp4_home_s6_multislot_pac_ab_20260907/RESULTS.md). 아래 본문은 준비 단계의 이력이며, ‘아직 플래시하지 않았다’, ‘검증 전’, 6슬롯 최소 예시 등의 상태는 이 후속 결과로 갱신된다. 현재 타이밍의 13슬롯 한도를 BRRS 자체의 최대 슬롯 수와 혼동하지 않는다.

## 사용자 정정 반영: 물리 노드 수와 슬롯 수는 별개

최종 물리 TX6대는 DATA6슬롯을 의미하지 않는다. 기존 본문의6슬롯/6000보고/76.8kbps 계산은 노드당1슬롯인 최소 구성 예시에만 해당한다. 주시험을6슬롯으로 고정하지 않는다.

현재 M32/G250/SB3000/SP2500/10ms 설정에서 DATA 슬롯 타이밍 최대는13, 비컨 포맷 표현 상한은32다. BRRS 자체 슬롯 상한은 이 두 구현값으로 정의하지 않는다. 12슬롯이면6대에2슬롯씩 균등 배정(총12000보고/1000SF), 13슬롯이면한 노드3슬롯·나머지5노드2슬롯(총13000보고/1000SF)이 가능하다. 추가 슬롯 소유자/위치에 따른 편향은 비교 설계에서 다뤄야 한다. 현재 기본 빌드는 repeats=1이므로6을 넣기만 하면6슬롯이 되는 점을 주의하고, 더 많은 슬롯은 custom sequence 등으로 명시한다.

반복 소유 슬롯은 재전송으로 손실을 숨기는 용도가 아니다. 각 슬롯을 별도의 신규 보고 기회로 세며, 실제 펌웨어 DATA 식별·카운터와 모든 예정 슬롯을 검증해야 한다. PER 분모는 무조건노드당1000이 아니라 SF수×그 노드의 배정 슬롯수다. 각 노드 PER와 슬롯별 손실을 모두 기록한다. 비컨 누락1회는 해당SF에 그 노드가 맡은 슬롯수만큼 예정 보고 손실을 일으킬 수 있다.

새보드 연결 확인: 로컬INIT1050270933, 원격TX1050211584/1050273888/1050282818/1050208509/1050227627/1050204212 총6대 인식. 기존3대역할은유지하고 새3대의역할은 아직플래시하지 않았다. SSH정상, 잔여캡처없음. 근거: exp4_vehicle_s6_preparation_20260907/connected_boards.json.

권장 시험 범위는 균등12슬롯 기준 및 최대13슬롯 부하를 포함하도록 수정한다. 최대13슬롯은 마지막버스트예약7469us로SYNC준비7500us까지명목31us만남으므로, 용량계산과 별도로 실제처리·예약지연검증이필요하다. 타이밍·버퍼·수집검증후 같은슬롯배정으로PAC8/PAC4비교한다. 이번정정반영에서새빌드·플래시·RF실험은수행하지않았다.

사용자 확정 방향(2026-09-07): 최종 실험은 실제 차량을 빌려 TX6대로 진행한다. NLOS6.9m와 집 배치는 차량 대여 전 준비를 위한 다양한 모사/스트레스 환경이다. 특정 NLOS 배치를 복제하거나 한 위치에서만 낮은 PER을 얻는 것을 최종 목표로 삼지 않는다. 차량 예상 운용 범위의 여러 거리·차폐·방향·사람/상태 변화에서 여섯 TX 각각 PER<1%를 지향한다.

유지 제약: M32, 무재전송, BRRS TDMA 및 비수신 구간 절전. 비교 묶음 동안 물리 배치·역할·전원·포트를 고정한다. 환경 변화는 묶음 사이에 의도적으로 수행하고 기록한다. 조건별·노드별 결과와 worst node를 보고하며 다른 환경 합산 평균으로 실패를 숨기지 않는다. 비컨 누락으로 인한 미송신도 예정 보고량 기준 손실에 포함한다. GPIO/통신 오류·읽기/종료 마커 무결성을 별도로 검사한다. 소스 변경·GitHub 업로드 보류는 기존 세션 범위대로 관리하며 이 문서 작성은 플래시/실험/업로드가 아니다.

## 6대로 조기에 전환할 이유

실제6개 보드의 서로 다른 RF링크, 슬롯0–5, 비컨 수신, 연속 오류와 다음 슬롯 재진입, SPI/버퍼 처리, USB 허브 전원/동시 RTT 수집을 차량 전에 검증한다. TDMA가 정상이라면 TX가 늘어난다는 이유만으로 동시 송신 충돌이 생기는 것은 아니다. 3대가 슬롯을 반복하는 시험은 처리량/예약 시험에 유용하지만 서로 다른6개 물리 링크의 검증을 대신하지 못한다.

## 읽기 전용 소스 확인

분석 소스: DW3_QM33_SDK_1.0.2_exp4_rxlead_20260907.
- INIT/TX BRRS_SENSOR_NODES 범위1..7; 빌드 helper sensor-count1..7, 역할N2..N8 지원. 따라서 TX6대=INIT1+TX N2..N7 총7대 구성이 코드 구조상 가능하다.
- M32/PAC8/G250/lead25/SB3000/SP2500/10ms 유지 시 슬롯347us.
- 6슬롯 RMARKER:3000,3347,3694,4041,4388,4735us.
- 코드의 마지막 DATA burst 종료 예약5040us, 다음 SYNC 준비7500us까지2460us. 이 설정의 계산상 슬롯한도13. 수치상6개를 넣기 위해 M/guard/SF를 바꿀 필요는 없다. 실제6노드 바이너리 빌드 및 하드웨어 검증은 아직 하지 않았다.
- 1000SF이면 노드당1000, 전체6000 reports; 16B app offered76.8kbps, 각노드100Hz 유지.
- 기존 캠페인 run_side.py/audit_run.py는 TX목록N2/N3/N4와3슬롯을 고정한다. HEX의S값만 바꾸고 그대로 실행할 수 없다. 신규S6 이미지와 명시적7개 serial mapping, 캡처/검증6노드 확장이 필요하다.
- 마지막 실제 장비 확인은 INIT933, TX584/888/818 총4대다. 추가3대의 준비 상태를 사용자에게 질문했고 serial은 확인 전 추정하지 않는다.

## 권장 순서

1. 실제TX6대의 역할/serial을 확인하고, S6 PAC8 기준 펌웨어 및7보드 수집/검증을 준비한다. 쉬운 배치에서6000보고·마커·슬롯·송신/비컨·시스템 검증으로 구성 자체를 확인한다.
2. 약한 링크가 있는 현재와 같은 모사 배치에서S6 PAC8 기준을 수집한다. 노드 수 증가와 PAC변경을 동시에 시작하지 않는다.
3. 같은S6 배치에서 PAC8→PAC4→PAC8 비교. INIT DATA PAC와 규정된 파생 SFDtimeout만 변경, 비컨 및 TX 설정 유지. 모든 실행을 보존하고 비컨 누락/실제 송신 손실을 분리한다.
4. 좋은 링크/일부 약한 링크/여러 약한 링크·방향 변화 등 미리 기록한 여러 환경에서 동일 후보를 확인한다. 한 위치에서만 잘 되는 설정을 피하고 환경별 각노드PER를 비교한다. 임의 환경에서 무조건 수신한다는 보장 대신 차량에서 예상할 운용 범위를 명시한다.
5. 후보를 고른 뒤 선택에 쓰지 않은 배치와 긴 반복으로 재검증하고, 차량에서는 최종 실제 배치·TX6대로 확인한다. 1000SF는약10초라 빠른 선별용이며 단1회0%를 장기 보장으로 해석하지 않는다.
