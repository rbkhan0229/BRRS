집계 분모는 사전에 예약된 9000개 보고를 그대로 유지한다. 3회차 N2는 최초 비컨을 놓쳐 첫 수신 seq=2, 비컨 999/1000, DATA 999/999 송신, INIT 수신 999였다. 이 1개 누락을 분모에서 제거하거나 순수 DATA 복호 손실로 잘못 분류하지 않는다. 1·2회차 전 노드와 3회차 N3/N4는 각각 비컨 1000/1000, 송신 1000/1000이다. 누락/실패 실행을 버리거나 좋은 실행으로 대체하지 않았다.

### 무결성 및 예외

- 12개 원시 로그의 크기/SHA-256, 보드 ID/역할, 펌웨어 SHA-256, 기록 커밋이 기대값과 모두 일치했다.
- INIT deadline miss, delayed RX/TX late, RDB mismatch/incomplete, overrun, SPI 오류/timeout, RX timeout = 0.
- 모든 TX delayed-TX late 및 scheduled-SYNC delayed-RX late = 0. PHY 전환 자기검증 모두 통과.
- **무선 오류는 존재:** INIT RX error 이벤트 256 / 270 / 291. 3회차 N2는 SYNC RX error 1, SYNC timeout 0, 비컨 누락 1. 이는 무선 손실 기록이며 시스템 오류 0과 혼동하지 않는다.
- 세 INIT 실행 모두 기존 5% 기준을 초과하여 metadata `status=FAIL` 유지. `collection=PASS`만으로 성능 성공이라고 판단하지 않는다.
- [읽기 전용 감사](audit_reproduction.py)에서 PER 실패를 보존하면서 후속 무결성 검사를 모두 수행했고 통과했다. TX verifier의 PASS는 비컨 무손실을 뜻하지 않으므로 3회차 N2의 `beacon=LOSS`를 별도 출력/기록했다.
- TX 준비는 모두 첫 시도에서 READY; worker/orchestrator 로그에 재시도, 재접속, 예외 경고 없음. INIT 세 수집도 재접속/예외 없음.

### 해석과 다음 단계

“유전원 허브를 사용하지 않아서만 발생한 문제이며 교체하면 해결된다”는 설명을 이번 결과는 뒷받침하지 않는다. 다만 실제 보드 전압/리플을 측정하지 않았고 같은 허브의 전원 ON/OFF도 아니므로 전원 관련 원인을 전부 제외할 수는 없다.

다음 원인 분리는 현재 허브·전원·배치·역할을 고정한 상태에서, M32/PAC8/S3/G200 및 SB/SP=2000/2000 조건으로 fast switch ON/OFF를 각 3회 교차 비교하는 순서가 적절하다. 이 진단 조건은 동결 기준과 구분한다. 이후 필요하면 wait budget과 SPI를 각각 분리한다. 허브 자체의 인과 효과를 주장하려면 기존 허브 복귀 등 시간 변화 대조가 추가로 필요하다. 이번 단계에서는 PHY/wait 변경 및 B/C 실험을 시작하지 않았다.

## 목적과 비교 한계

같은 날 확보한 기존 허브 기준 데이터와 비교하여 높은 M32 PER가 허브 교체 및 외부 전원 연결 후 달라지는지 확인한다. 기존 허브는 어댑터 연결을 지원하지 않아 **허브 자체도 교체**했다. 전원만 바꾼 통제 비교가 아니므로, 차이가 나타나도 전원 공급만의 효과로 귀속하지 않는다. 허브/USB 토폴로지 변화와 순차 실행의 시간 변화가 함께 존재한다.

사용자는 교체 허브의 외부 전원 어댑터가 연결됐으며 보드 위치·방향은 그대로라고 확인했다. 물리 상태는 사용자 확인이며 별도 전압 측정은 수행하지 않았다. 허브 모델, 어댑터 정격, 포트별 전압은 아직 기록되지 않았다.
