# M32 고손실 원인 분리 — 보드 교체 직전 상태

2026-09-03. 원인은 아직 부품/물리 메커니즘 수준으로 확정되지 않았다. 아래는 원래 위치·역할·유전원 허브를 고정한 측정 결과다. 동결 브랜치와 진단 브랜치의 펌웨어 소스는 수정하지 않았고 push도 하지 않았다. 기존 플래그로 진단 이미지를 빌드하고 결과만 추가했다.

## 이번 순서·간격·SPI 비교에서 확인한 것

공통 M32/PAC8/S3/lead15/SP2002, full dwt_configure, polling, IRQ/프로파일링 OFF, 1000슈퍼프레임/실행. 특별히 표시하지 않은 경우 최적화 SPI ON. 현재 공식 최종 설정이나 새 NLOS 성능 데이터로 합산하지 않는다.

10개 유효 실행 모두 각 TX1000/1000 및 비컨1000/1000. 보드·펌웨어/원시 로그 해시·파라미터·소스별 슬롯 분류와 수신 개수 일치. 스케줄 late, deadline miss, RDB mismatch/incomplete/resync/recovered, overrun, SPI 오류/timeout 등 검사 항목은0. PHY 오류와 PER는 높으며 모든 실행은 **FAIL_PER**다. 유효 수신0 실행을 성공으로 취급하지 않았다.

`additional_integrity_audit.json`은10개 실행을 다시 검사한 결과다. 원래 펌웨어 verifier가 별도로 강제하지 않던 RDB resync/recovered=0, source→observed slot/owner, buffer별 합계도 로그 분석 스크립트에 추가해 재검증했다. 펌웨어/harness 판정 코드는 바꾸지 않았다.

Legacy SPI 준비 r1은 INIT 실행 전에 TX 수집 대기가 만료됐으므로 ABORTED_BEFORE_INIT으로 보존했고 RF 비교에 넣지 않았다. 유효 legacy 재실행은r4다.

## 아직 단정할 수 없는 것

- 특정 보드 불량, 안테나/경로, 수신기 재시작 상태 중 단일 원인은 미확정이다. AGC/DGC, EMI, 전압 문제를 직접 측정한 증거는 없다.
- 현재 구현은 첫 슬롯 delayed-RX 후 DATA 버스트 내부 immediate rearm이다. 후속 슬롯까지 각각 독립 delayed-RX라는 설명은 맞지 않다. 이 구조는 이번 진단에서 새로 변경한 것이 아니다.
- 오류 대부분은 FINT-only로 남아 세부 PHY 실패 원인을 판별하기 어렵다. CRC 오류0이 모든 손실에서 CRC가 정상이었다는 뜻은 아니다.
- 첫 슬롯으로 옮겨도888 PER11.5~12.4%이므로 순서 변경만으로 M256 수준의 신뢰도를 얻었다고 주장할 수 없다.
- 과거 Aug25 같은888/N3의 M32 PER2.2%는 실제 로그지만 당시 collectionFAIL이었다. wait/펌웨어가 달라 역사적 회귀 원인은 아직 닫지 않는다.
- 비교는 시간 순서대로 수행했으며 무작위화·충분한 반복·차량 검증이 아니다. Wilson 구간은 실행 간 변동이나 상관 손실을 설명하지 못한다. 사람 통행 보고는 받지 않았으나 현장을 직접 관찰한 것은 아니다.
