# Exp2 실패-CIR 후보 진단: 다음 자택 시험용 준비본

상태: **오프라인 코드·검증기 준비, 펌웨어 빌드·실기 검증 전**. 이 문서는 V2 Standard의 공식 Exp2/Exp5 결과를 바꾸지 않는다. 기존 실행 스택·원본 로그·STOP은 그대로 두고 별도 브랜치에서만 시험한다. RF·플래시·리셋은 이번 준비에 포함되지 않는다.

## 목적과 해석 한계

Exp2의 성공 수신 CIR만으로 손실 원인을 설명하면 성공 조건부 선택 편향이 생긴다. 이 옵션은 오류 시점에 프리앰블 검출과 CIA 완료가 보고된 경우의 **후보 원시 CIR**을 제한적으로 보존한다. 송신 프레임의 payload/CRC가 없으면 해당 송신 프레임을 직접 식별할 수 없으며, 슬롯·시각 연결은 별도 검증 대상이다. 프리앰블 미검출에는 그 시도의 CIR이 없다. 수집 후보를 순수 채널 CIR, 실패 순간의 확정 FP-SNR, 차량 RMS로 표기하지 않는다.

## 현재 준비된 구현

- 기본값 OFF. brrs_exp2_capture_v3.sh의 RX --failed-cir-diag만 옵션을 켠다. TX 또는 Exp5에서는 켤 수 없다. 캐시된 HEX/ELF의 모드 stamp 불일치를 차단한다.
- 오류·timeout의 기존 ACCUM 읽기가 성공한 뒤 RXPRD, 1 ≤ ACCUM ≤ M, CIADONE, CIAERR=0, FP 인덱스 범위를 확인한다. 하나라도 맞지 않으면 원시 CIR을 읽지 않고 사유만 센다.
- 게이트를 통과하면 현재 오류를 정리하거나 다음 RX를 재무장하기 **전** Ipatov 64 complex tap을 읽는다. FP 앞 16 tap부터 시작한다. 오류 종류당 최대 3건, 전체 최대 12건이며 RF 중에는 RAM에만 저장한다.
- RF 종료 후 FAIL_CIR_DUMP_START → 오류별 FAIL_CIR_HEADER/64개 FAIL_CIR_RAW → FAIL_CIR_DUMP_DONE을 RTT channel 1에 출력한 다음 기존 EXP2_DONE을 출력한다. 별도 검증기는 행 누락·중복·범위·계수·종료 마커를 검사하고 JSON sidecar를 만든다. 이는 **로그 완전성 검사**이며 파형의 물리적 유효성을 보증하지 않는다.
- Exp2의 성공 프레임 CIR_CSV, TX/RX/PER 계산, 기존 공식 판정식은 바꾸지 않았다. 추가 SPI 읽기가 이후 수신/PER에 주는 영향은 아직 미검증이다.

## 다음 주 자택 A/B 전에 필요한 게이트

1. Air에서 분리 브랜치·툴체인·이미지 해시를 고정하고 OFF/ON을 각각 직렬 build-only 한다. RAM/BSS 여유와 ELF 매크로·구성 확인이 필요하다. Ubuntu 펌웨어 빌드 결과를 대체 근거로 사용하지 않는다.
2. 이번에 준비한 파서·스크립트 오프라인 테스트와 기존 테스트를 통과시킨다. 진단 ON 이미지를 OFF로 잘못 재사용하거나 그 반대를 시도하면 stamp 검사에서 막혀야 한다.
3. 사용자가 현 배치·전원·보드 독점·RF 시작을 다시 확인한 뒤 별도 격리 root에서 동일 CH/M/PAC/code/lead/송신 조건의 OFF/ON을 교차 비교한다. 각 케이스의 공식 PER와 START/END/readback/HALT/STOP을 독립 보존한다. 오류가 0건이라면 로그 완전성만 확인한 것이며 실패-CIR 유효성 검증 완료가 아니다.
4. ON에서 delayed-late, 다음 슬롯 수신 누락, 시스템 오류, PER 변화가 있는지 OFF와 대조한다. 후보 샘플은 상태 비트·ACCUM·FP·파형을 함께 검토한다. 같은/유사 파형이 나왔다고 즉시 진짜 실패 CIR로 승격하지 않는다. 결과가 불명확하면 공식 Exp2에는 OFF 버전을 유지한다.

Exp5의 300-tap 실패-CIR 확대와 V2 Standard/논문 반영은 이 A/B 결과를 보고 별도 결정한다. M1024 Exp5에서도 성공 수신 전체의 품질 요약과 원시 CIR 30개 전 구간 분산 선택 불일치는 별개 과제다.
