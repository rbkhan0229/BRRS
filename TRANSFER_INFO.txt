Submission experiment block runner:
  cd Drivers/API
  ./brrs_run_experiment.sh <stage0|exp1|exp2|exp3|exp4> <role> \
    <environment> [distance] [options]

This selects one experiment only and then runs its complete condition/repetition
matrix for the current physical placement. See
Drivers/API/BRRS_SUBMISSION_AUTO_RUN_KR.md.

Every experiment defaults to one run per condition. Add --repeats N explicitly
when collecting repeated paper data. Stage0 defaults to all 41 integer lead
values from 0 through 40 us in a fixed randomized order. Stage0 uses --leads
to select sweep points; Experiments 1-4 use --lead <us> to freeze the lead
selected from Stage0. The Experiment 1-4 default is --lead 15.

Open this SES project:
Drivers/API/Build_Platforms/nRF52840-DK/dw3000_api.emProject

Select the named build configuration for the required experiment and node.
Do not use generic Debug/Release for submission experiment runs.

Stage0 automatic capture (32-symbol preamble, tail margin 0 us):
  cd Drivers/API
  ./brrs_stage0_capture.sh tx 15 1 <environment> [distance]
  ./brrs_stage0_capture.sh rx 15 1 <environment> [distance]

The lead argument selects an existing Stage0_L<lead>_T0_Init configuration.
Lead values 0 through 40 us are available. Start TX first, then RX.

Experiments 1-3 use an explicit three-copy END beacon handshake. Their automatic
verifiers require end=1 on TX and end_tx=3 on INIT so two independent laptops
cannot silently advance on different case boundaries.
After the final DATA transmission, the TX node immediately returns to the SYNC
PHY and logs BRRS_END_RX_ARMED before waiting for the END beacon. This avoids
depending on the ordinary mid-superframe CONFIG_SWITCH_US path at run end.

Experiment 1 automatic capture (Stage0-selected fixed lead, tail 0 us):
  cd Drivers/API
  ./brrs_exp1_capture.sh tx 32 1 <environment> [distance] --lead 15
  ./brrs_exp1_capture.sh rx 32 1 <environment> [distance] --lead 15

Preamble values 32, 64, 128, and 256 symbols are available. Each run has
2,000 measurement opportunities. collection=PASS means that the requested
configuration ran to completion without scheduling/configuration faults.
link=LOSS and the reported PER preserve real RF loss and do not invalidate a
complete log.

Experiment 2 result semantics:
- expected=1000 is the number of measurement opportunities.
- rx is the number of successfully received frames.
- One valid CIR_CSV row is required for every successful RX frame.
- collection=PASS means rx, valid_cir, dump_count, and CIR_CSV rows agree.
- link=LOSS means rx < expected and is reported separately from collection status.
- per_x1000 is PER percent multiplied by 1000 (2.90% is 2900).
- status is the collection status, not the zero-PER condition.
- TX completion is verified from the structured EXP2_TX_DONE marker rather than
  the human-readable FINAL STATS title.

Experiment 3 automatic capture:
  cd Drivers/API
  ./brrs_exp3_capture.sh tx A 1 <environment> [distance] --lead 15
  ./brrs_exp3_capture.sh rx A 1 <environment> [distance] --lead 15

The submission block runner rotates A/B/C across three runs as A-B-C, B-C-A,
and C-A-B. Start TX first, then RX.
TX verification requires exactly 1,000 EXP3_TX_CSV rows and a successful
EXP3_TX_DUMP_DONE marker. The legacy brrs_exp3_flash_and_log.sh is disabled
because its separate J-Link connections could lose RTT data.

Experiment 4 automatic capture (default guard 200 us, default lead 15 us):
  cd Drivers/API
  ./brrs_exp4_capture.sh N2   32 2 1 <environment> [distance] --lead 15
  ./brrs_exp4_capture.sh N3   32 2 1 <environment> [distance] --lead 15
  ./brrs_exp4_capture.sh init 32 2 1 <environment> [distance] --lead 15

Start every sensor command first and INIT last. The script builds only its own
role with the requested preamble, sensor count, and guard. It then flashes,
captures RTT channel 1 through the same PyLink connection, verifies the current
revision 21 schedule/double-buffer/node totals, and writes a raw log plus
metadata. See
Drivers/API/BRRS_EXPERIMENT4_AUTO_CAPTURE_KR.md.

Experiment 4 automatic multi-probe TX capture:
  cd Drivers/API
  ./brrs_run_experiment.sh exp4 tx <environment> [distance] \
    --sensors 3 --repeats 3 --lead 15

The TX runner discovers exactly --sensors USB J-Link probes, sorts their serial
numbers, and cyclically rotates the N2..N(S+1) roles on each run. It prints and
saves every role-to-serial assignment, starts all node captures concurrently,
and prints EXP4_MULTI_TX_READY when INIT may be started. Run the matching INIT
suite on the other computer with the same sensor count and repeat count.

The default capture backend is pylink and requires:
  python3 -m pip install pylink-square

Use --force only when intentionally repeating the same run number. The old raw
log is retained as .prev.<time>. Use --method telnet only for comparison or
diagnosis.

RX verification succeeds only when:
- the firmware uses the new explicit collection/link/PER fields;
- expected=1000 and the requested preamble agree;
- rx, valid_cir, dump_count, CIR rows, unique rx_seq values, and unique cycle
  values are internally consistent;
- each CIR row has the expected node, preamble, and number of columns.
