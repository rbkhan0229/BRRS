## 2. 현실적 제약을 제외한 정의 부합성

| BRRS 요소 | 확인된 현재 구현 | 판정 |
|---|---|---|
| 비컨을 공통 시간 기준으로 사용 | INIT의 SYNC TX timestamp, TX들의 SYNC RX timestamp와 공지 offset 사용 | 부합 |
| M·PSDU 길이·데이터율·슬롯 소유자/간격 사전 공지 | 공통 beacon format에 포함, TX가 검증·적용 | 부합 |
| 할당 슬롯에서 송신 | TX가 비컨 기준 절대 시각으로 delayed-TX 수행 | 부합 |
| 각 서브슬롯의 예정 시각에 수신 창 개방 | 첫 슬롯만 delayed-RX, 뒤 슬롯은 앞 이벤트 처리 후 CMD_RX | **핵심 소프트웨어 차이** |
| 스케줄 밖 불필요한 탐색 제한 | DATA burst 동안 슬롯별 FWTO 비활성화, 다음 패킷까지 탐색 지속 | **슬롯별 수신 창과 다름** |
| 송신기별 미니 프리앰블로 채널 재획득 | 모든 DATA에 M32 유지, 표준 패킷별 수신 경로 사용 | 방향 부합. CIR 품질이나 M32의 충분성을 이 실행에서 별도 검증하지 않음 |
| SFD·PHR·자율 검출 제거 | DW3000 표준 수신 경로에 남음 | 요청대로 하드웨어 제약으로 분리. delayed-RX만으로 제거할 수 없음 |
| guard 확보 | G250 적용 | guard의 존재는 부합. 논문의 Tg=5us 이용률 수치와는 다른 조건 |
| 비수신 구간 절전 | INIT burst 종료 시 RF off, TX는 다음 비컨 시각에 delayed-RX | 버스트 밖 수신 제한은 있음. 슬롯 사이 RX off는 없고, 깊은 sleep·전류 절감량은 이 검토에서 입증하지 않음 |
| 재전송 없이 각 센서 보고 | 이번 조건은 각 TX 1,000 attempt/1,000 success, 1,000 SF | 사용자 조건 부합 |

따라서 “SFD/PHR를 제거할 수 없는 것만 빼면 BRRS를 그대로 구현했다”는 설명도 정확하지 않다. 수신 시점 제어에도 구현 가능한 차이가 남는다. 현재 결과의 적절한 표현은 **비컨 동기화 M32 TDMA에서 burst 수신을 사용한 BRRS 부분 검증**이다.

반대로 표준 PHY 경로가 남아 있다는 이유만으로 비컨·TDMA·프리앰블 축소까지 모두 BRRS와 무관하다고 할 수도 없다. 논문 IV 실험 4 자체가 이상적 BRRS 완성품과 DWM3000 기반 부분 검증을 구분한다.

PSDU 안의 8바이트 공통 헤더는 PHY PHR와 다르다. 이번 PSDU는 공통 헤더 8B + 앱 데이터 16B + FCS 2B = 26B이며, MAC/앱 메타데이터를 PSDU에 포함하는 것 자체는 제시된 BRRS 정의 위반이 아니다. 다만 이용률 계산에서는 앱 유효 데이터와 전체 PSDU를 구분해야 한다. 큰 guard와 SB/SP를 유지한 이번 실험만으로 논문의 이상적 이용률을 실측 달성했다고 주장할 수 없다.

## 4. 제시된 원인 설명에서 맞는 부분과 과장된 부분

“비컨으로 수신 시각을 알고 있는데도 뒤 슬롯에서 긴 탐색을 계속한다”는 지적은 구현과 일치한다. BRRS가 시간 정보를 이용해 탐색 부담을 줄이겠다는 전제를 후속 슬롯에서는 충분히 활용하지 않는다. 그래서 슬롯별 scheduled delayed-RX는 이 하드웨어에서 BRRS의 수신 전제를 더 직접적으로 시험하는 기준 구현으로 적합하다.

엄밀한 정의에서 중요한 것은 RF 전원을 매번 껐다 켜는 행위 자체가 아니라 예정된 상관·수신 창의 제어다. RF는 켜 두더라도 별도로 슬롯별 상관 창을 제어하는 수신기라면 개념적으로 부합할 수 있다. 현재 CMD_RX burst 경로에서는 그런 별도 창 제어가 확인되지 않는다.

그러나 다음 세 가지는 아직 결론으로 사용할 수 없다.

1. **M32는 반드시 매 슬롯 delayed-RX여야 한다:** M32의 보편적 필요조건으로 입증되지 않았다. 프로토콜에서 중요한 것은 예정된 창의 제어이지 특정 칩 명령 이름 자체가 아니다. 다른 구현 수단으로 동등한 시각/창 제어를 해도 개념적으로 가능하다.
2. **delayed-RX이면 검출이 제거된다:** DW3000의 CMD_DRX도 정해진 시각에 켜진 뒤 preamble hunt를 수행한다. 사전 무신호 탐색을 제한하는 효과와 하드웨어 검출 단계를 생략하는 효과는 다르다.
3. **앞에서 오래 탐색했으므로 M32 심볼을 이미 소모했다:** 실제 패킷이 오기 전의 대기 시간이 송신된 M32 심볼을 자동으로 깎는 것은 아니다. 거짓 획득, 수신 진입 시점, 이전 패킷 후 수신 상태, 획득·동기화·채널 추정 품질 등 구체적 연결 기전을 관측해야 한다.

긴 탐색에서 불필요한 획득 사건이 늘거나 약한 패킷이 불리한 상태에서 시작될 가능성은 검토할 가설이다. 아직 현재 기록은 그 내부 상태를 직접 보여주지 않는다.

논문 III-B의 30–33dB 및 M8–16은 채널 추정에 충분할 것이라는 추정이다. 처리 이득 식 하나로 해당 NLOS의 SNR, 다중경로, 동기화 오차, 필요한 PER을 보장하지 않는다. 이상적 수신기에서도 M32 성공은 환경에 대한 측정이 필요하다.

- **다른 배치의 반례:** 집에서 RX를 건조기 뒤에 둔 실행에서는 이미 delayed-RX인 첫 슬롯 N2가45.4%, N3/N4는0%였고 SFD timeout454회였다. 이는 “후속 슬롯의 긴 탐색이 모든 M32 손실의 필요 원인”이라는 주장을 제한한다. 그 배치는 현재 NLOS와 달라 현재 N3의 수신 이력 가설을 직접 반증하지는 않는다.
- **오류 종류 해석:** RXFSL은 데이터 부분의 Reed–Solomon 복호화 중 수정 불가능 오류를 의미한다. preamble 검출 실패와 같은 뜻이 아니다. 불충분한 획득/채널 추정이 이후 복호화를 악화시켰을 가능성은 있으나 이 카운터만으로 연결을 확정할 수 없다. SFD timeout은 preamble 검출 이후 SFD를 제한 시간에 찾지 못한 사건이다.

따라서 가설의 우선순위는 높지만 인과 확정은 아니다. 이번 실행의 손실199개와 RX 오류164회도 일대일 대응하지 않는다. FWTO/PTO가0이라는 결과 역시 창 타임아웃을 끈 구조에서 무검출 누락이 없다는 뜻은 아니다.

## 6. 다음 구현의 가치와 A/B 조건 — 이번에는 미구현

슬롯별 scheduled delayed-RX를 구현할 가치는 **두 가지 독립적인 이유**로 있다. 첫째는 현재 N3 고손실에서 수신 창/재진입 방식의 영향을 확인하는 것이고, 둘째는 개선 여부와 별개로 BRRS의 예정된 수신 창 전제를 더 충실하게 시험하는 것이다.

권장 비교는 동일 소스 기준에서 A=current burst, B=각 슬롯의 bounded scheduled-RX를 선택하게 하는 방식이다. 원래 TX HEX·역할·M32/PAC8·G250·lead15·SB/SP·배치·허브 전원·출력을 유지한다. 첫 슬롯의 시각과 공통 초기화는 양쪽에서 동등하게 유지하고, 비수신 구간 RF off와 재전송 없음 조건을 유지한다. 과거 HEX와 새 빌드 B만 바로 비교하면 기존 소스 차이까지 섞이므로, 같은 소스로 만든 A의 동작도 기준과 확인해야 한다.

B에는 아래가 함께 필요하다.

- 슬롯마다 비컨 기준 절대 RX-open 시각과 유한한 종료 조건을 설정한다. 현재 Exp4 helper를 그대로 반복 호출하면 FWTO가 여전히0이므로 충분하지 않다.
- 패킷이 전혀 검출되지 않거나 SFD/PHR/CRC/RXFSL 오류가 나도 예정된 다음 창으로 진행한다. 가짜 검출/오류 횟수나 처리 중 추정 슬롯이 실제 슬롯 시간을 밀거나 건너뛰지 않게 한다.
- RXFCG/CIADONE 및 double-buffer 상태를 안전하게 처리하고 다음 창 준비를 guard 안에 끝낸다. 기존 CIA 완료 대기를 성급히 제거하지 않는다. 준비가 늦으면 late를 명시적으로 기록한다.
- 실제 창 예약/종료, RX 이벤트 시각, TX RMARKER, 오류·버퍼·수집 종료를 기록하되 진단이 제어 시점을 바꾸는 영향을 관리한다.
- A/B를 반복·교차하고 각 노드 PER<1%로 판정한다. 창 방식과 복구가 함께 바뀌는 1차 A/B는 그 변경 묶음의 효과를 검증한다. B가 좋아져도 추가 분리 없이는 긴 탐색 시간, 오류 복구, 수신 재진입 상태 중 하나를 단독 원인으로 확정하지 않는다.

B에서도 고손실이 남으면 “슬롯별로 예약하면 해결된다”는 설명은 약해지고, 동일 M32에서 획득/동기화/CIR 품질과 실제 수신 진입 상태에 대한 추가 진단이 필요하다. 이 경우에도 현재 burst 방식이 BRRS의 창 제어 전제를 완전히 시험하지 못한다는 설계 판정은 그대로다.
