# BRRS Exp4 차량 실험 준비 상태와 최소 실행 구성

> 범위 정정: 이 문서는 Exp4 중심의 차량 예비시험 하위 계획이다. 전체 차량 실험은 Stage0~Exp5이며, 전체 준비 완료 여부와 최신 순서는 [전체 실험 구성 정정](FULL_EXPERIMENT_READINESS.md)을 기준으로 한다.

2026-09-07. 사용자 확정: 프렁크 RX 1대, 범퍼 TX 2대, 운전석/조수석 TX 각 1대, 트렁크 TX 2대. 총 RX 1 + TX 6 = 7개 보드. 반복을 줄이고 서로 다른 후보/차량 상태를 우선 확인한다.

## 권고와 준비 판정

**lead25의 기존 후보로 짧은 차량 예비 비교를 할 장비·펌웨어·수집 도구는 준비됐다. PAC별 lead 탐색과 차량 최종 설정은 아직 확정되지 않았다.** 사용자 지적에 따라, PAC4/PAC8 각각 lead를 탐색한 뒤 선택한 PAC+lead 조합을 차량에서 비교하도록 순서를 수정한다. [PAC × lead 비교 계획](PAC_LEAD_COMPARISON_PLAN.md)이 최신 선택 절차다. 현재 lead25 후보만으로 PAC의 최적 성능을 비교했다고 판단하지 않는다.

최종 RX 위치가 프렁크인 만큼, 해당 배치를 직접 평가할 본 실험에는 프렁크가 있는 차량을 우선 권한다. 내연기관 차량도 차량 통신의 예비시험에는 쓸 수 있지만, RX를 엔진룸 등으로 바꾸면 수신 위치와 주변 구조가 달라진 별도 실험이다. 엔진룸 결과를 프렁크 결과로 대체하지 않는다. 차종·연식별 실제 공간을 확인한 후 정하며 모든 전기차에 같은 프렁크가 있다고 가정하지 않는다. 프렁크의 실제 예시는 [Tesla Model Y 제조사 설명서](https://www.tesla.com/ownersmanual/modely/en_eu/GUID-356E0168-47E5-400F-AD83-4F1B86C7D991.html)에 있다. 이는 특정 모델 대여 추천이 아닌 공간 구성의 참고다.

차량에서 실제로 한 번 이상 측정해야 PAC와 링크별 우열을 알 수 있다. NLOS 6.9m의 TX 3대 시험에서는 PAC8/P25의 N3 합산 PER 0.25%, PAC4 1회는 3.2%였다. 최근 집 TX 6대/13슬롯에서는 PAC4가 앞뒤 PAC8보다 두 배정 모두 낮았다. 집의 PAC4/SFD64는 N4 4.25%로 더 낮게 관측됐지만 1회·비동시 비교이고 목표에는 실패했다. 서로 다른 환경·노드 수·슬롯 배정 결과를 합산해 차량 성능을 예측하지 않는다.

## 공통 무선·슬롯 설정

M32, 채널 9, 6.81 Mbps, G250, SB/SP 3000/2500us, SF 10ms, 슬롯 347us, 슬롯별 scheduled delayed-RX, 기존 SPI 최적화와 RF 비수신 구간 정책을 유지한다. lead25 기준은 RX 창122us/FWTO119UUS다. lead 탐색에서는 시작과 창 길이를 함께 조정해 모델상 종료점을 유지하고, PAC별 선택 lead를 차량 비교에 사용한다. TX 출력·비컨 PHY·재전송 정책을 바꾸지 않는다. ACK/오류 기반 재전송은 사용하지 않는다. 실제 전류/에너지 절감률은 별도 계측 대상이다.

주 비교는 **물리 TX 6대·DATA 13슬롯**, sequence `2345672345673`이다. N3가 3슬롯, 나머지는 2슬롯을 맡는다. 1,000 SF에서 N3 offered=3,000, 나머지는 각 2,000, 전체 13,000이다. 16B app payload 기준 offered는 전체 166.4 kbps, N3는 300회/s, 나머지는 200회/s다. 여러 슬롯을 맡는 것은 별개의 예정 송신 기회이며 중복 수신 성공으로 손실을 숨기지 않는다.

13은 현재 G250/SB/SP/SF 타이밍에서의 상한이다. 비컨 포맷의 표현 상한 32나 BRRS 자체 용량과 구분한다. 12슬롯 균등 배정 `234567234567`은 이미 PAC8 기준 이미지와 검증 이력이 있으며, 차량에서 구조적 예약/버퍼 오류가 나타날 경우 부하 분리 진단으로 사용할 수 있다. 단순 PHY 손실 때문에 13슬롯 실패를 숨기는 대체 성공 조건으로 쓰지는 않는다.

## 후보 선택

기존 준비 후보 A=PAC4/SFD37/lead25, B=PAC8/SFD33/lead25, C=PAC4/SFD64/lead25는 보존한다. A/B는 lead25 기준점이며 최종 최적 후보가 아니다. 최초 비교 전에 PAC4/PAC8 각각 lead15/25/35를 같은 범위에서 평가한다. 현재 집 배치가 유지된 경우 기존25 결과를 참고하고15/35만각1회, 기본4회로 빠르게 선별할 수 있다. 과거 결과와 새 결과의 시간 차이는 명시한다.

차량 주 비교는 **PAC4+선택 lead4**와 **PAC8+선택 lead8**이다. 두 선택값이 같을 수도 있고 다를 수도 있다. SFD는 각각37/33을 적용하고,64는 별도 진단으로 남긴다. 둘 중 어느 PAC이 우세한지 미리 정하지 않는다. 각노드 PER와 예약 무결성, 주변lead의 안정성 및 수신창 길이를 함께 평가한다. 세부 원리·타이밍표·순서는 [공동 비교 계획](PAC_LEAD_COMPARISON_PLAN.md)에 있다.

## 현장 최소 실행 순서

|---|---|---|---|
| 0 | 설치·급전·SSH·serial·노트북 절전 설정·문/후드 닫힘 확인 | RF 없음 | 수집 가능한 현장 상태 확인 |
| 1 | 정차, 문/창문/후드/트렁크 닫힘, 차내 인원 고정, PAC4+선택 lead4 | 1,000 SF ×1 | lead 탐색 후 후보 검증 |
| 2 | 위치·인원·차량 상태 동일, PAC8+선택 lead8 | 1,000 SF ×1 | 각각 선택한 PAC+lead 조합 비교 |
| 3 | 두 조합 모두 실패하면 양쪽 PAC에 같은 탐색 기회를 주는 인접 lead 진단을 검토 | 필요 조건만 각1회 | 차량에서 lead 민감도 확인; SFD 변경은 후순위 |
| 4 | 잠정 선택 후보 고정, 탑승자 조건만 변경 | 1,000 SF ×1 | 사람에 의한 변화 확인 |
| 5 | 같은 후보·배치에서 정차 전원 상태만 변경 | 1,000 SF ×1 | 차량 전원 상태 차이 확인 |
| 6 | 앞 단계에서 가장 불리했던 유효 조건, 최종 후보 고정 | 10,000 SF ×1 목표 | 선택에 쓴 짧은 실행과 별개로 약 100초 확인 |

정차 전원 상태 변경은 배선·장착이 적합한 범위에서 수행한다. 내연기관 엔진룸에 임시 장비를 둔 경우 시동 ON 시험을 자동으로 포함하지 않는다. 내연기관으로 바꾸면 RX 설치와 배선 조건부터 따로 정해야 한다. 제조사도 뜨거운 엔진/배기 부품의 위험을 명시한다([Ford 설명서](https://www.fordservicecontent.com/Ford_Content/Catalog/owner_information/2KF012720AB_202206_enGBR_.pdf)).

단계 4–5는 동일 조건 반복이 아니라 운용 상태의 변화다. 집에서 PAC별 lead를 선별한 뒤 차량에서 두 조합이 통과하면 **차량의 짧은4회 + 긴1회**로 구성한다. 집의 새로운 lead 선별4회는 차량 실행 수와 별도다. 차량에서 두 조합이 모두 실패하면 성공 확인 단계로 넘어가지 않고 필요한 진단만 정한다. 실제 설치 범위에 불필요한 차량 상태는 미리 제외할 수 있다.

1,000 SF의 RF는 약 10초지만 현재 7보드 준비·수집·flash readback은 한 실행 약 1분 수준이다. 최근 한 실행은 약 52초였다. 현장 네트워크·설치 시간에 따라 달라지므로 전체 소요 시간을 10초×횟수로 계산하지 않는다.

**단계 6의 10,000 SF 구성은 아직 준비 완료가 아니다.** 현재 확인된 HEX는 1,000 SF이고, 빌드 옵션은 10,000까지 지원하지만 실제 긴 실행용 INIT/TX 이미지·RAM 사용·수집 제한 시간을 확인해야 한다. INIT 수집 제한이 현재 90초라 그대로는 100초 RF를 담을 수 없다. 노드별/슬롯별 분모와 종료 조건까지 긴 실행에 맞춰 별도로 검증해야 한다. 기존 결과 폴더와 집 환경 metadata를 재사용하지 않고 차량 전용 실행 폴더·manifest를 만든다. 이번 요청에서는 빌드/플래시를 추가하지 않았다.

## 판정과 기록

- 각 TX별 예정량/RX/PER, 비컨 수신/누락, TX attempt/success/late를 기록한다. 비컨 누락에 따른 미송신도 예정량 기준 PER에 포함한다.
- 전체 평균이 낮아도 한 노드 PER가 1% 이상이면 목표 실패다. 시스템·수집 무결성 통과와 무선 PER 통과는 별도로 표시한다. RX 0이나 마커/수집 실패는 PASS로 처리하지 않는다.
- SFD/PHR/CRC/RXFSL/FWTO/PTO, wrong source/slot/SF, delayed RX/TX late, RDB·SPI·overrun·수집 timeout 및 종료 마커를 보존한다.
- 같은 차량 상태 안에서 후보를 비교하며, 각 상태의 PER를 따로 판단한다. 여러 차량 상태를 합산한 평균으로 약한 링크를 가리지 않는다.
- 의도한 탑승자/전원 상태 변화는 별도 유효 시험 조건이다. 정적 측정 중 예정하지 않은 문 열림·사람 통행·USB 이상은 기록해 오염/무효 실행으로 보존한다.
- 차량 모델/연식, 장착 사진, 위치·방향, 문/후드/트렁크 상태, 탑승자, 전원·허브·케이블 연결, 시각, serial 및 HEX SHA256을 기록한다.
- 짧은 1회 통과는 후보 선별이며, 100초 통과도 임의의 모든 차량·배치에서 성능을 보장하지 않는다. 현재 실험은 실제 DW3000 PHY의 SFD/PHR를 사용하는 BRRS MAC 구현 평가이며, 논문의 이상적 SFD/PHR 제거 PHY나 이용률 달성을 직접 입증하지 않는다.
